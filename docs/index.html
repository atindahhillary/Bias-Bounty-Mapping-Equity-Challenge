One reference layer is quietly deciding the whole score

coverage_gap_score is the mean of whichever components (roads, buildings, places) have a reference to compare against. Across all 9,379 tracts, those three components aren't missing equally:

99.9%Buildings defined
99.7%Places defined
67.5%Roads defined

When a tract has no named highway and no HIFLD facility and no CBP establishment on record, its entire score collapses to the building component alone -- and Overture's building coverage is good almost everywhere, so that lone surviving number is usually near zero. A real, populated community can score as "near-perfect coverage" while the two components that actually matter for emergency dispatch and evacuation are simply absent from the number, not measured, not zero.

This runs opposite to the intuitive guess. Naively, tribal and rural tracts should be the ones missing data. They aren't: rural tracts lack a highway only 7.3% of the time versus 38.2% for urban tracts -- a large rural tract is far more likely to have some stretch of state highway crossing it than a small, purely residential urban tract is. The masking problem concentrates in small, urban, non-tribal tracts, which is itself the more useful thing to know, since it means no rural/tribal adjustment alone would fix this scoring rule.

Why it matters

  • Dispatch and evacuation routing built on this metric can't tell "excellent road mapping" from "never checked" -- both read as the same near-zero score.
  • A 7,115-person tract (48001950402) scores identically to a fully-instrumented downtown block, purely because Overture happens to have mapped its buildings well.
  • The tribal example (40143009014, Eastern OK) shows this isn't only a Texas/Arizona artifact -- it reproduces in a tribal statistical area in the drought/heat region the challenge itself flagged as high-risk.
  • FEMA/NGO coverage metrics using this score at face value would rank these communities as adequately mapped. The honest answer is "unmeasured," not "low-gap" -- and those call for very different responses before a wildfire, heat wave, or drought.

Reproducing this

  1. Run python scripts/run_pipeline.py against the public challenge bucket (no credentials needed) → data/tracts.csv.
  2. Filter to parts_defined == 1 and coverage_gap_score < 0.05 -- the exact query behind the table above.
  3. Cross-reference transport_defined/building_defined/poi_defined to confirm which single component carries the score, and pop_total to exclude uninhabited tracts.
